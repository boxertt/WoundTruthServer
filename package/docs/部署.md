# 部署

`./deploy/up.sh` 是唯一入口。它先取得用户级锁 `woundtruth-deploy.lock`（优先放在 `XDG_RUNTIME_DIR`，否则放在 `~/.local/share/woundtruth/`），再调用 `deploy/check-env.sh`。检查失败就退出，此时还没有启动 Ollama，也没有下载模型。服务名是固定的，所以同一用户下的两个目录副本不能同时部署。

这套成功判定还没有在 8000 空闲的机器上完整跑通，不要把它写成已经验证过的一键部署。

## 机器必须已经具备

检查脚本不代为安装这些东西：

- Ubuntu 24.04，架构 aarch64
- 系统自带的 Python 3.12，并且能创建虚拟环境
- `nvidia-smi` 能看到 GPU，计算能力不低于 12.0（现网 GB10 是 12.1）
- 已安装 `ollama` 命令
- 内存总量不少于 64 GiB，可用不少于 48 GiB
- 仓库所在磁盘可用不少于 80 GiB
- `ss`、`curl`、`sha256sum` 和 `flock`

内存数字按现网机器填写：总量约 120 GiB。`qwen3.6:35b` 磁盘上约 23 GB，要在统一内存里跑，所以空闲内存用 48 GiB 做门禁。

## 检查通过之后的顺序

1. 确认 `bin/woundtruth-web`、`bin/sam2-worker` 可执行，且 `web/dist/index.html` 存在。缺文件就停，避免白下几十 GB。
2. 启动系统服务 `ollama.service`。若未运行，脚本使用免密 `sudo` 启动。做不到就停。
3. 等到 `http://127.0.0.1:11434/api/tags` 有响应。
4. 用 Python 3.12 创建 `runtime/sam2-venv`。已有环境会核对 torch 2.9.1、CUDA 13、transformers 5.15.1，以及 `import cv2` 和 `opencv-python-headless==4.12.0.88`。对不上就停，并提示删掉该目录后重跑。
5. 安装锁定版本。torch 和 torchvision 只从 `https://download.pytorch.org/whl/cu130` 安装。`opencv-python-headless` 从 PyPI 安装，因为工人启动时要 `import cv2`，而编译没有把 OpenCV 打进二进制。
6. 下载 `facebook/sam2.1-hiera-tiny` 到本次专用的临时目录。`deploy/sam2-model.sha256` 里的 `config.json`、`model.safetensors` 和三份处理器配置都要校验通过，才改名到 `runtime/models/facebook-sam2.1-hiera-tiny`。失败时只删除这次创建的临时目录。
7. 本机没有 `qwen3.6:35b` 时执行 `ollama pull qwen3.6:35b`。
8. 下载结束后再查一次 8000。`ss` 查询失败不算空闲。每一条监听记录上的每一个 PID 都要属于 `woundtruth.service`，不能只核对最后一个；其中一条必须包含该服务的 `MainPID`。有任何一个 PID 无法确认归属就停。然后写入用户级单元并 `restart`。只有 `restart` 之后出现了新的 `MainPID`，才把这个 PID 记为本次实例。
9. 180 秒内同时满足这些条件，才打印 `http://127.0.0.1:8000`：`/api/health` 的 `status` 为 `ok`；`/api/sam2/status` 的 `status` 为 `ready`，并且 `configured` 和 `resident` 都是 `true`；8000 的全部监听记录都属于本次服务，且 `MainPID` 仍是这次 `restart` 得到的 PID。`resident=true` 只说明工人子进程仍在，不证明已经完成过一次分割。

端口规则：

- 8000 空闲才算通过。若已被占用，每一条监听记录上的每一个 PID 都必须属于 `woundtruth.service`，不能只保留看得到 PID 的那几条，也不能只看一行里的最后一个 PID。`ss` 失败要单独报错。被别的进程占用就停，脚本不杀进程。
- 11434 空闲，或者已经是本机 Ollama，才算通过。查询失败不等于空闲。

`data/records` 里如果已经有文件，检查直接失败。病历由部署方在检查通过后自行放到 `data/`，不要放进 git。

私钥检查覆盖待发布的普通文件，不看扩展名。`BEGIN CERTIFICATE` 可以保留。文件读不到，或者遍历失败，都算检查失败。`runtime/`、`data/` 和 `.git` 不在这套待发布扫描里。

## 网页进程的环境变量

服务单元把下面这些交给 `bin/woundtruth-web`。以后编译可执行文件时按这些名字读取：

| 变量 | 值 |
|---|---|
| `WOUNDTRUTH_DATA_DIR` | `<仓库>/data` |
| `WOUNDTRUTH_STATIC_DIR` | `<仓库>/web/dist` |
| `WOUNDTRUTH_SAM2_PYTHON` | `<仓库>/runtime/sam2-venv/bin/python` |
| `WOUNDTRUTH_SAM2_WORKER` | `<仓库>/bin/sam2-worker` |
| `WOUNDTRUTH_SAM2_MODEL` | `<仓库>/runtime/models/facebook-sam2.1-hiera-tiny` |
| `HF_HUB_OFFLINE` | `1` |
| `TRANSFORMERS_OFFLINE` | `1` |
| `HF_DATASETS_OFFLINE` | `1` |

网页监听 `0.0.0.0:8000`，同时提供页面和 API。不要再开一个前端开发服务器。

SAM2 工人由网页进程拉起，使用上面的 Python 和模型目录。权重下载完成之前，网页不会启动。

## 可执行文件约定

两个入口都在 `bin/`，背后是 Linux aarch64 的编译目录。

- `woundtruth-web` 读取上表环境变量，提供 `/api/health` 和 `/api/sam2/status`。
- `sam2-worker` 是单个可执行文件，接受 `--serve --model <目录>`，从标准输入读一行 JSON，向标准输出写一行 JSON。它使用系统 Python 3.12，PyTorch 从 `WOUNDTRUTH_SAM2_PYTHON` 所在的虚拟环境加载。

发布分支更新后，在开发机执行 `./compile/sync-release.sh`。已经同步过的提交不会重复编译。需要强制重编时加上 `--force`。

## 失败时停在哪里

| 现象 | 停在哪 | 已经做过什么 |
|---|---|---|
| 系统、GPU、内存、磁盘、端口不符合 | `check-env.sh` | 没有下载，没有启动 |
| `bin/` 缺文件 | `up.sh` 的包检查 | 没有下载 |
| Ollama 起不来 | 启动 Ollama 这一步 | 没有重建 SAM2 环境 |
| torch、CUDA、transformers 或 OpenCV 对不上 | 核对虚拟环境 | 不覆盖已有环境 |
| 权重校验失败 | 下载之后 | 只删除这次的临时目录，不启动网页 |
| 180 秒内健康检查不通，或监听进程不是本次服务 | 最后一步 | `restart` 一旦成功，旧进程已经被 systemd 换掉。之后只有当前 `MainPID` 仍等于这次记下的 PID 时，才停止服务。PID 已经变了就不按服务名停止，并写明留下的 PID。若 Ollama 是这次脚本启动的，它会继续运行 |

停止网页：

```bash
./deploy/down.sh
journalctl --user -u woundtruth.service -n 80 --no-pager
```
